# 알려진 문제

나중에 고칠 것들을 적어둔다. 고치면 해당 항목을 지우고 커밋 메시지에 남긴다.

---

## 1. AI 프로그램을 닫아도 MCP 서버가 안 죽고 남는다

**상태:** 미수정 (2026-09-17 기록)

### 증상

AI 프로그램(Claude Code 등) 세션이 끝났는데도 `교실_퀴즈.exe mcp` 프로세스가 계속 살아 있다.
세션을 여닫을 때마다 하나씩 쌓인다.

### 실제로 관측한 것 (2026-09-17)

- 08:49:08 에 뜬 `교실_퀴즈-0.0.0-e4f03bb.exe mcp` (PID 15072) 가 09:47:23 까지 생존.
  약 1시간.
- 부모였던 `claude.exe` (PID 6016, VS Code 확장 세션) 는 진작 종료됨.
  09:44 시점에 `Code.exe` 조차 하나도 안 떠 있었는데 자식은 살아 있었다.
- 살아 있는 동안 상태: CPU 0.125초, 메모리 6.3MB, **리스닝 소켓 0개**, 연결 0개.
  즉 게임 허브는 안 뜬 유휴 상태였다. 수업에 영향은 없다.
- 종료 사유는 로그상 정상 EOF:

      2026/09/17 08:49:09 MCP 서버 시작 (퀴즈 폴더: C:\Users\user\Downloads\quizzes)
      2026/09/17 09:47:23 MCP 서버 종료(입력 끝)

- 로그에 같은 초에 "MCP 서버 시작" 이 2~3번 찍힌 날도 있다 (09-16 10:00:31 x2, 10:07:23 x3).
  인스턴스가 겹쳐 뜨는 상황이 실제로 존재한다.

### 원인 분석

코드는 잘못이 없다. `mcp.go:67-73` 의 `dec.Decode` 는 stdin 이 EOF 면 바로 빠져나온다.
**문제는 EOF 가 늦게 도착하는 것.**

Windows 에서 부모가 `bInheritHandles=TRUE` 로 자식을 띄우면, 나중에 뜬 다른 자식들이
먼저 뜬 자식의 stdin 파이프 *쓰기* 핸들 사본을 함께 물려받는다.
그러면 부모가 죽어도 파이프의 쓰기 끝이 안 닫히고, 마지막 핸들 보유자가 사라질 때까지
`ReadFile` 이 블록된 채로 남는다 → EOF 없음 → 프로세스 생존.

**주의: 이건 정황에 맞는 설명이지 확정된 원인이 아니다.**
09:47:23 에 정확히 어느 프로세스가 핸들을 놓았는지는 확인하지 못했다.
고치기 전에 재현부터 할 것.

### 재현 방법

1. VS Code 의 Claude Code 확장에서 세션을 열어 퀴즈 MCP 를 붙인다.
2. `Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*mcp*' }` 로 PID 확인.
3. VS Code 를 완전히 종료한다.
4. 같은 명령으로 자식이 남아 있는지 본다. 부모 PID 생사는
   `Get-Process -Id <부모PID>` 로 확인.
5. 남아 있다면 `Handle.exe` (Sysinternals) 로 해당 파이프의 핸들을 누가 쥐고 있는지 추적.

### 고칠 방법

파이프 EOF 에 기대지 말고 **부모 프로세스를 직접 감시**한다.

- 시작할 때 부모 PID 를 얻어 `OpenProcess(SYNCHRONIZE, ...)` 로 핸들을 잡아둔다.
- 별도 고루틴에서 `WaitForSingleObject` 로 기다리다가 풀리면 종료한다.
- Windows 전용이므로 `*_windows.go` 에 넣고, 다른 OS 는 no-op 으로 둔다.
  (`console_windows.go` / `netmedia_windows.go` 와 같은 패턴)

### 고칠 때 반드시 같이 볼 것

**수업 중 강제 종료 위험은 없다 (처음 기록의 전제가 틀렸음, 2026-09-17 리뷰).**
`mcp` 모드는 게임 허브를 띄우기 전에 끝난다 — `main.go:51-53` 의 `case "mcp": runMCP(); return`
이 `listenLAN`(:67)·`newHub`(:73)보다 앞이다. 학생이 붙는 서버는 교사가 더블클릭한 **다른 프로세스**다.
(관측된 "리스닝 소켓 0개" 와도 맞는다.) 그러니 부모가 죽으면 조건 없이 종료해도 된다.
퀴즈 저장은 임시파일→rename 이라 도중에 죽어도 파일이 깨지지 않는다.

대신 이것들을 봐야 한다:

- **부모가 중간 래퍼일 수 있다.** 클라이언트가 `cmd /c`·node 중간 프로세스를 거쳐 띄우면
  바로 위 부모는 금방 끝난다. 그걸 감시하면 시작하자마자 종료돼 **AI 연결 자체가 망가진다.**
  클라이언트별 실제 부모 사슬부터 확인할 것.
- **PID 재사용.** 이미 죽은 부모 PID 를 다른 프로세스가 받았을 수 있다. 핸들을 연 뒤
  그 프로세스 생성 시각이 우리보다 앞인지 확인할 것.
- **영향은 "유휴 프로세스"보다 크다.** 실행 중인 exe 는 윈도우가 파일을 잠근다. 남은 `mcp`
  프로세스가 옛 exe 를 쥐고 있으면 설명서 4장의 "새 버전으로 덮어쓰기"·옛 파일 삭제가
  "사용 중인 파일" 로 실패한다. 교사가 실제로 겪을 증상은 이쪽일 가능성이 높다.

### 다음 단계

1. **시뮬레이션으로 재현** — 부모 역할 프로그램이 상속 가능한 파이프로 `mcp` 자식을 여러 개
   띄운 뒤 부모만 죽여, 자식이 EOF 없이 살아남는지 본다. 래퍼(`cmd /c`) 경유도 같이 본다.
2. 재현되면 부모 감시를 넣는다(래퍼 건너뛰기·생성 시각 확인 포함).
